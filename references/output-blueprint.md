## 三层输出总览(事实 / 分析 / 结论)

第 5 步跑完,产出**三层文件**,各司其职、互不混):

| 层 | 格式 | 装什么 | 给谁看 |
|---|---|---|---|
| **事实层** | xlsx(单文件·5 sheet) | mcp / 抓取返回的**结构化原始记录**,原样沉淀,**不放文本** | 想用 Excel/Numbers 打开做二次分析、核对原始数据的人 |
| **分析层** | md(大而全) | 完整推理过程 + **所有文本证据**(字幕原文 / 评论原话 / 信号推导 / 各层小结卡 / 判断定调推理链) | 想复盘"怎么得出这个结论"、审证据的人 |
| **结论层** | md(精简) | 决策报告(下文三件套 + 调用消耗),关键数字内联,可独立看懂 | 拍板"做不做 / 怎么测"的决策者 |

**引用关系(不重复抄)**:
- 分析层引用事实层 —— 如「达人侧见 `原始数据.xlsx`「TK达人」sheet(9 条),其中垂直美妆仅 1 位」,摘关键不贴整表。
- 结论层关键结论指向分析层 —— 如「四维判读推导见分析过程.md §4」。
- 文本证据(字幕原文 / 评论聚类)**只在分析层**,不进 xlsx(塞不进表格)、不进结论层(太长)。

## §5 第 5 步 · 方案定制引擎

**输入**:`{ 机会类型(主+辅), 证据深度(L1/L2/L3), 三层素材 }` → **生结论层三件套**,同时汇总分析层 + 落事实层 xlsx。

**证据深度定精细度**:
- 只到 L1 / L2 → **方向级**(内容角度 + 钩子方向)
- 进 L3 → **脚本级**(钩子 / 演示动作 / CTA 可直接拍)

### 三件套(结论层核心,机会类型定制)

#### ① 内容方向(优先 ≥ 3 + 不建议)

每个方向给:**角度 + 钩子方向**(+ L3 则补脚本骨架:钩子/演示/CTA)。

- **不建议方向**(并说明为什么):同质化严重 / 播放高但商业弱 / 依赖大达人或大制作 / 合规风险。
- **物料语言 = 目标市场原文**(见末尾「输出语言」)。

#### ② 首轮达人画像(内容参考组 + 首轮合作组)

- **内容参考组**(3~5 个):可学其内容的达人。给:粉丝量 / 内容风格 / **为什么值得学**(挂依据)。
- **首轮合作组**:**⭐ 硬约束——只列有联系方式(邮箱)的**(不盲假设能联系上)。给:达人 / 粉丝 / 平均播放 / 带货销量 / **契合度评分 + 理由** / 联系方式(平均播放·带货销量来自 `creator_search` 返回,判断达人质量用)。
- 匹配评分由 skill 计算**并展示依据**(数据规范 ⑧:搜索只是召回,评分是 skill 算的);达人明细在事实层 `原始数据.xlsx`「TK达人」sheet,结论层只列入选者。

#### ③ 最小测试计划(按机会类型自适应配比,不一刀切)

- **记录指标**:播放 / 互动 / 点击 / 成交。
- **判据**:写清**放大 / 修改 / 停止**的触发条件(如「单视频播放 > X 且互动率 > Y% → 放大该角度」)。

### 机会类型 × 方案侧重(主配比表)

| 机会类型 | 内容方向 | 达人 | 测试计划 |
|---------|--------|------|--------|
| **品类红利型** | 宽口径多角度 | 两组并重,抢占位 | 宽铺:3-5 角度 × 5 达人 × 7-10 天,**重覆盖** |
| **差异化型** | 聚焦差异点(1-2 角) | 找契合差异点的 | 聚焦:1-2 角度 × 3 达人 × 10-14 天,**重验证** |
| **内容驱动型** | 重钩子,多版本 | 偏内容参考 | 迭代:1-2 角度 × 多版本 × 7-14 天,**重找爆款** |
| **达人撬动型** | 给可套框架 | 首轮合作组为主角 | 达人筛:少角度 × 多达人 × 7-10 天,**重找对人** |

① 角度 + 钩子方向(+ L3 脚本骨架)
② … ③ …

【6 · 本次调用消耗】

[零依赖手填场景:0 次(全程手填,无 mcp 调用)]

【7 · 范围与边界】(必出 · 管理读者预期)

- 变现路径:TK Shop 开店门槛 / 挂车选型 / 佣金结构 / FBA↔TK 物流衔接
- 投流执行:Spark Ads 预算 / 定向包 / 放量策略
- 达人建联补全:本报告给首轮**种子达人 + 补查路径**(见【4】),凑齐测试所需人数靠用户
- 亚马逊运营深度:该 ASIN 衰退**原因**诊断 / 亚马逊搜索词趋势(本报告亚马逊侧只做输入理解 + 健康度标衰退)
- AI 视频适配:达人精灵无该字段,本工具不验证

### ③ 事实层 `原始数据.xlsx`(单文件·5 sheet,结构化原始记录)

一个 xlsx 文件、按数据源分 5 个 sheet(一个文件打开就是分好的表,Excel/Numbers 友好)。每 sheet:**首行中文表头 + 每行一条原始记录**(字段贴合该数据源,见 [`mcp-reference.md`](mcp-reference.md) 返回字段);skill 计算的判读列(可联系/垂直度/归组等)加在末尾,标注 `[skill 算]`。

| sheet 名 | 来源 | 核心字段(中文表头) |
|---|---|---|
| 亚马逊商品 | `asin_detail` + `asin_prediction` | ASIN / 标题 / 品牌 / 类目 / 价格 / 评分 / 评分数 / 月销量(预估) / BSR(大类) / BSR(子类) / 上架时间 / 卖家类型 / 配送方式 / 数据来源 |
| TK商品召回 | `product_search` | 商品ID / 标题 / 价格 / 类目 / 近30天销量 / 近30天销售额 / 评分 / 评分数 / 带货达人数 / 带货视频数 / 店铺名 / 履约类型 / 是否同形态竞品`[skill 算]` |
| TK视频召回 | `video_search` | 视频ID / 标题 / 时长秒 / 发布时间 / 播放量 / 点赞 / 评论 / 收藏 / 转发 / 互动率 / 近30天带货销量 / 创作者 / 创作者粉丝 / 内容角度归类`[skill 算]` |
| TK店铺 | `shop_search`(或降级反推) | 店铺ID / 店铺名 / 类目 / 在售商品数 / 均价 / 近30天销量 / 达人数 / 视频数 / 评分 / 24h回复率 / 2天发货率 / 店铺类型 / 运营模式 / 数据来源(专搜/降级反推) |
| TK达人 | `creator_search` | 达人handle / 昵称 / 地区 / 粉丝数 / 互动率 / 平均播放(avgViewsPerVideo) / 带货视频数(videoCnt) / 带货销量 / gpm(每千次播放销售额) / 带货商品数 / 带货分类(goodsCategory) / 邮箱 / 联系方式数 / 可联系`[skill 算]` / 垂直度`[skill 算]` / 归组(合作组/参考组)`[skill 算]` |

**怎么生成(给 agent)**:用 python `openpyxl` 生成 —— 每个数据源的召回结果先整理成「表头行 + 数据行」,逐个 `wb.create_sheet(title=sheet名)` 写入;首行表头加粗 + 深色底色、`ws.freeze_panes='A2'` 冻结表头、列宽按内容自适应(中文字符算 2 宽)。存到子目录下 `原始数据.xlsx`。不依赖 pandas;openpyxl 是唯一第三方依赖(`pip install openpyxl`,多数 python 环境预装)。

> **文本类原始素材不进 xlsx**:字幕原文、评论聚类、商品理解卡 —— 它们是证据而非结构化记录,进分析层。xlsx 只装"能成行成列"的。
> **字段取舍**:以 mcp 实际返回为准,返回缺的字段留空不编造(数据规范:缺失标「未验证」)。
> **零依赖手填**:没有 python 环境时,直接在 Excel/Numbers 新建 `原始数据.xlsx`,按上表建 5 个 sheet 手填,文件名与 sheet 名照旧。

## 三层落盘(子目录聚合)

第 5 步跑完,把三层文件落到 **skill 目录下 `output/`** 的**一个子目录**里(一次验证 = 一个子目录):

```
output/
  YYYY-MM-DD_[市场]_[品名关键词]_[档位]/     ← 目录名(沿用原单文件命名格式,含档位一眼看结论)
    ├─ 结论.md                  ← 决策报告(精简)
    ├─ 分析过程.md              ← 完整验证 + 证据(大而全)
    └─ 原始数据.xlsx            ← 事实层(单文件·5 sheet:亚马逊商品/TK商品召回/TK视频召回/TK店铺/TK达人)
```

- **目录命名**:`YYYY-MM-DD_[市场]_[品名关键词]_[档位]`
  - **日期**:跑报告当天(ISO `YYYY-MM-DD`)。
  - **市场**:目标市场码(US / GB / ID / TH / VN / …)。
  - **品名关键词**:品牌 + 品类核心词,**≤20 字**,提炼自标题、不照搬长标题;空格用 `-`;避开文件名非法字符(`/ \ : * ? " < > |`)。
  - **档位**:值得测试 / 有条件测试 / 证据不足(与结论层【1】一致)。
  - **示例**:`2026-08-09_US_ELROEL-变色粉底棒_值得测试/`
- **子文件命名**:固定简洁名(`结论.md` / `分析过程.md` / `原始数据.xlsx`),不重复日期品名(目录已含)。
- **重测同名品**:不覆盖旧目录 —— 目录名加 `-v2`/`-v3` 后缀(如 `..._值得测试-v2/`),留对比。
- **零依赖手填场景同样落盘三层**:手填时事实层 xlsx 标「数据来源:用户手填」(建 5 个 sheet 手填,见 §③),分析层/结论层照常;确认门仍过(确认商品理解 + 市场,与数据来源无关)。
- **用户指定别处**:路径听用户的。

## 输出语言

- **报告解读**(分析/判断/建议/理由)= **中文**。

## 用户掌舵(再次强调)

方案是**建议不是命令**。参数(达人数量 / 测试周期 / 角度数)**可改** —— 给「为什么这么配」的依据(挂机会类型 + 证据),让用户能自己调。最终 go/no-go 在用户。
