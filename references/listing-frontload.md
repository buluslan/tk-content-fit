# listing-frontload · 第 0–2 步:Listing → TK 搜索策略

> 本 skill 的**独有资产**。已有 cold-start 类 skill 默认「你已有 TK 方向产品」;本 skill 输入是**亚马逊爆品 Listing**,必须先翻译成 TK 本地化搜索策略——召回质量取决于这一步,是真实 gap。
> 对应 SKILL.md 骨架第 0/1/2 步。

---

## §0 第 0 步 · 预筛层(低门槛,极端才劝退)

**原则**:默认放行 + 打风险标签;**可拍性终审权交给第 3 步 L1 的 video 实际召回**——预筛只做极端止损,不越权终判。

**极端不适合(0 call 劝退)**:
- 纯 B2B / 工业件(无内容属性,普通用户不关心)
- 纯规格件(无可演示差异,如工业螺丝、通用耗材)
- TK 明确违禁品类

**放行但打风险标签**(这些不劝退,但标注,后续验证重点看):
- 低可视化(工业耗材、抽象服务)→ L1 video 终审
- 强合规(医疗功效、夸大宣传风险)→ 内容方向规避疗效话术
- 高决策(客单价极高、需长决策)→ 测试计划放长周期
- 强季节性 → 测试计划卡时间窗

**输出**:预筛结论(放行 / 极端劝退)+ 风险标签(若有)。

> 落实哲学「用户掌舵」:预筛不硬拦,只标风险;即便打了风险标签也进下一步,让数据说话。

## §1 第 1 步 · 需求锚定(商品理解卡)

**两层**(数据-功能解耦:必填层 skill 自给,增强层可选)。

### 必填层(skill 从 Listing 提取,无会员也行)

| 字段 | 怎么填 |
|------|--------|
| 品类 | Listing 标题/类目提炼 |
| 核心功能(一句话) | 这个产品本质做什么 |
| 解决的痛点(TOP3) | 从五点描述/Bullet 提炼 |
| 使用场景(TOP3) | 产品用在什么场景 |
| 目标人群 | Listing 受众暗示 |
| **⭐ 可视化演示点** | **单独提炼,见下** |
| 亚马逊价格 | $ 价格 |
| 英文品类词 | 用于第 2 步品类词 |

**⭐ 可视化演示点(关键,单独提炼)**:决定后续 ①L1 可演示性粗判 ②L3 脚本演示动作。
> 问自己:**这个产品在视频里能"演"出什么?** 凡能演的都列出。
> 典型可演维度:前后对比 / 使用过程 / 效果可视化 / 痛点放大 / 组装/拆解 / 极端测试 / ASMR 触感。
> 不可演的(纯软件、抽象服务、规格件)→ 标「低可演示」,后续判据会用到。

### 可选增强层(sellersprite 或用户手填)

销量(预估)/ BSR / 搜索词热度 / **评论 UGC 聚类**(高价值,见下)。

- 有 sellersprite → `asin_detail` / `asin_prediction` / `competitor_lookup` 取结构化数据,`review` 拉评论原文(参数见 [`mcp-reference.md`](mcp-reference.md))。
- 没有 → 用户手填已知数据或粘贴热评,或跳过(必填层足够支撑后续)。

**⭐ 输入健康度检查(输入含 ASIN 且取了 `asin_prediction` 时必做)**:确认输入的爆品**当下还活着**,而非已衰退——避免拿「曾经的爆品」当活跃品验证、误导后续判断。
- 看 `asin_prediction` 的**销量趋势**(近 1–3 个月日均 vs 历史峰值)+ **BSR 走势**(近月 vs 历史最好排名)。
- **衰退信号**(任一即标):近期日均销量趋零(如 ≤ 历史峰值 5%),或 BSR 大幅恶化(如跌出 10 倍以上)。
- 命中衰退 → 商品理解卡 + 报告【1】标「⚠️ 输入 ASIN 已衰退:近 N 月日均 ~X 单 / BSR 从 A 跌到 B。**本报告验证的是品类契合度,非该 ASIN 当前销售前景。**」照常验证品类(用 TK 侧同形态竞品的活跃度,而非该 ASIN 的亚马逊销量判断品类)。
- 哲学「数据诚实」:不拿衰退品当活跃爆品;但**衰退 ≠ 品类没戏**(可能只是该 ASIN/Listing 被竞品取代)。

**⭐ 评论 UGC 聚类(贯穿第 2/3 步的高价值增强)**:标题/五点是卖家视角的**卖货逻辑**,评论是用户视角的**使用逻辑**——后者正是 TK 脚本裂变的核心素材。从评论原文提炼:

- **真实使用场景**(用户自发说"在 X 场景用了它")→ 脚本钩子 + 第 2 步场景词源
- **痛点原话**(用户抱怨的真实表达)→ 痛点放大素材
- **意外用法 / 长尾人群**(卖家没写进五点的)→ 差异化角度
- **口语化表达** → 直接可做 TK 搜索词

> **筛选规则(防噪声)**:只要高频 + 近期 + 带细节的场景/痛点;短评、纯情绪评、刷评嫌疑、过时评扔掉。**评论场景 ≠ TK 内容机会**——它是假设生成器,是否真有戏仍要在第 3 步 TK 侧验证(见 [`tk-validation.md`](tk-validation.md) §3 L1)。

**信息不全时**:对应字段标「⚠️ 假设」,**不编造**;假设要在结论里显式说明,降置信度。

## §2 第 2 步 · 翻译(6 类 TK 搜索词矩阵 + 召回质量校验闭环)

### 核心认知:亚马逊标题词 ≠ TK 搜索词

| | 亚马逊 | TikTok |
|---|---|---|
| 搜索意图 | 精确品类(带着买的目的) | 内容 / 口语 / 场景(刷内容、找灵感) |
| 词的风格 | 规格化、品类化 | 口语化、场景化、情绪化 |

**直接拿亚马逊标题词搜 TK,召回会偏**(召回一堆不相关内容)。必须翻译成本地化搜索词。

### 6 类 TK 本地化搜索词

| 类 | 说明 | 示例(以"头皮按摩器"为例) |
|----|------|--------------------------|
| ① 品类词 | 最直,竞争最大 | `scalp massager` |
| ② 场景词 | 使用场景 | `shower routine` / `self care night` |
| ③ 痛点词 | 解决的问题 | `dry scalp` / `itchy scalp` |
| ④ 功能词 | 核心卖点 | `waterproof scalp brush` |
| ⑤ 竞品词 | 已知竞品/头部品牌 | (查到的竞品名) |
| ⑥ 口语表达 | TK 用户真实说法 | `thing for itchy head` / `shampoo brush thing` |

### 召回策略(分工,不是一锅搜)

- **主搜词** = 品类词 + 功能词 → 找同类商品(L1 product 用)
- **内容搜词** = 场景词 + 痛点词 + 口语表达 → 找内容土壤(L1 video 用)
- **辅证词** = 竞品词 → 定位竞争(L2 用)

### UGC 场景词增强(来自第 1 步评论聚类,可选)

评论里的 UGC 场景词是**卖家视角 Listing 覆盖不到的**真实场景/长尾用法(原料见 §1 评论 UGC 聚类)。有评论素材就补进搜词矩阵:

- **评论高频场景** → 追加为**内容搜词**(L1 video 用),验证 TK 有没有对应内容土壤
- **评论意外用法** → 单列为**差异化探针**(L1 video/product 各 1 次),看 TK 有没有人做过这个角度

> 这是 Listing→TK 单向翻译之外的**反向验证链路**:UGC 场景词 → TK 搜索 → 看有没有人做过。能发现 Listing 结构化词漏掉的内容机会。**评论只负责给方向,结论仍靠 TK 侧召回。**

### 召回质量校验闭环(关键,防垃圾召回)

**为什么校验**:词翻译错了,后面全跑偏。必须用一次探针确认"搜的词找对了人"。

1. **探针**:1 次 `product_search`(主搜词,`region`=目标市场,取首页结果)。
2. **判召回质量**(双指标:**绝对数主、占比辅**):
   - **同形态直接竞品数(主判据)** = 召回结果里**严格属于目标品类**者(同形态)的条数。严格口径:形态一致才算(如「体态矫正带」不含 color corrector 美妆色号、不含 brace 五金角码)。
   - **类目一致比例(噪音度标签)** = 同形态竞品数 ÷ 召回总数。< 50% = **召回噪音大**(词根多义污染重,如 corrector/brace/mask/roller 天然多义词根)。
   - 为什么绝对数主、占比辅:占比同时受分子(真竞品)和分母(污染总量)影响——多义词根品类占比天然低,但真竞品绝对数够就有效;占比低只说明噪音大,不说明召回没用。**占比不设硬死线**(避免为达标而放水口径,如把相邻形态硬算进来)。
3. **判据**:
   - **同形态直接竞品 ≥ 3 个** → 召回有效,进 L1。占比 ≥ 50% 标「召回可信」;< 50% 标「召回噪音大,结论降权」。
   - **< 3 个** → **换词重生**(优先换主搜词:品类词 ↔ 功能词 ↔ 口语,或加修饰词收窄/放宽),最多重生 **2 次**。
4. 重生 2 次仍 < 3 个 → **不死磕**:标记「召回不可靠,结论降权」,仍继续(用现有最好结果 + 全程标注降权)。

```

```

## 降级

| 故障 | 降级 |
|------|------|
| Listing 信息不全 | 商品理解卡对应字段标「⚠️ 假设」,结论降置信度 |
| sellersprite 不可用 / 不用 | 增强层跳过或用户手填;必填层足够跑 |
| `product_search` 不可用 | 用户手动判断召回是否靠谱 / 自填同类商品链接(进 L1 时喂入) |
| 召回重生 2 次仍不达标(同形态竞品 <3) | 标记降权,继续,全程声明 |
