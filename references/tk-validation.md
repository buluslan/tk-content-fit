# tk-validation · 第 3–4 步:三层验证 + 判断定调

> 后端研究编排。把第 2 步的 TK 搜索策略喂进三层验证,采四维信号,再汇总判断。
> 对应 SKILL.md 骨架第 3/4 步。

---

## §3 第 3 步 · 三层验证(L1 / L2 / L3)

**重排原则**:按**证伪效率**排序,最贵的(L3 字幕)放最深层、默认不触发。每层 = 一个「验证 + 交接」单元,跑完出层小结卡(格式见 SKILL.md §③),停/进交用户。

> 判据一律用**品类基线相对值**(美妆 500 个是红海,工业 50 个可能算繁荣),不用绝对阈值跨品类一刀切。

### L1 · 存在层(`product_search` + `video_search`)

**输入**:第 2 步的主搜词(product)/ 内容搜词(video)。有评论素材时,追加 UGC 场景词做反向验证(见下)。

| 验证什么 | 工具 | 信号 |
|---------|------|------|
| 同类商品数 / 价格带 / 销量集中度 | `product_search` | **商品需求信号** |
| 内容视频数 / 内容角度 / 可拍性终审 | `video_search` | **内容土壤 + 可拍性** |

- **价格带对标**:TK 同类价格区间 vs 亚马逊价——价差过大影响适配,标注。
- **内容角度归类**:开箱 / 演示 / 教程 / 对比 / 生活植入 / 痛点放大…,看角度多样性。
- **⭐ video 兼预筛终审**:召回到丰富演示向内容 = **推翻**第 0 步悲观标签;真一根演示向视频都没有 = **印证**「慎拍」。终审权在这,不在预筛。
- **UGC 场景词反向验证(可选,有评论素材时)**:用第 2 步从评论提炼的 UGC 场景词(意外用法/长尾场景)追加 `video_search` 1~2 次,看 TK 有没有人做过这个角度。
  - 召回到相关内容 = 评论场景在 TK **有土壤**,且可能是 Listing 结构化词覆盖不到的**差异化机会**。
  - 召回为空 = 评论场景是购买逻辑不是内容逻辑(或太新没人做),标注「评论场景 TK 待培育」,**不直接判死**。
  - 价值:补 Listing→TK 单向翻译的盲区,发现卖家视角漏掉的内容角度(原料见 [`listing-frontload.md`](listing-frontload.md) §1/§2)。

**call 量**:product 1 + video 1~2(+ UGC 探针 0~2)≈ 2~5 calls。
**止损点**:需求 + 土壤双低 → 建议停或换品(仍交用户)。

**L1 小结卡**要点:事实(N 条样本)→ 信号(需求/土壤/可拍性,**已覆盖 2 维 / 缺口 2 维:竞争·达人**)→ 建议 → 你来定(停 / 进 L2)。

### L2 · 竞争达人层(`shop_search` + `creator_search`)

**输入**:辅证词(竞品)/ 第 1 步目标人群。
> ⚠️ **creator 召回 keyword 影响弱 → 召回后必须 goodsCategory 二次过滤**:creator_search 的 `keyword` 对召回影响弱——召回常按全局带货销量排序、未必贴品类,换不同 keyword(品牌词 / 垂直内容词)召回顺序基本不变;`category_list` 中文值不识别(返回 0)。**正解:召回后按 `goodsCategory[]` 二次过滤**——用 **catName/cnCatName 含品类关键词**匹配(粉底 → `Foundation`/`粉底`);跨品类 catId 不同,从 raw 现场读。过滤后目标达人不足 5 则 `page_num++` 翻页;翻 3 页仍不够或 goodsCategory 全空(冷门品类)→ 回退 raw 召回,全程声明「达人侧未品类验证,L2 结论降权」。这是 §2 召回校验闭环(product 用同形态竞品数+噪音度判)在 creator 侧的平行扩展。
> ⚠️ `shop_search` 别用纯通用品类词(易召回白牌集合店),改用辅证词(竞品名)收窄。

| 验证什么 | 工具 | 信号 |
|---------|------|------|
| 头部集中度 / 销量归因 / 进入门槛 | `shop_search` | **内容竞争强度** |
| 达人数 / 粉丝分布 / 可联系性 / 两组雏形 | `creator_search` | **达人可获取性** |

- **头部集中度**:头部 N 店占销量比(高=红海,低=分散有机会);看**近期起量的新店**能否跑出(门槛信号)。
- **达人可联系性**:用 `mailAddress`(邮箱)+`contactList`(`{type,contactAddress}`)算 **可联系占比** = (有 mailAddress 或 contactList 的达人数) ÷ 样本数 → 决定首轮合作组能否落地(见 output-blueprint 硬约束)。**首轮合作组:可联系占比需达本次样本多数(过半),优先选有邮箱者**;占比明显偏低则声明「达人通道受限,首轮合作组规模下调」(无联系方式只能进内容参考组)。占比基线随品类不同(美妆偏高 / 工业·B2B 天然偏低),按品类基线判断,不下跨品类硬阈值。
- **两组雏形(垂直度 × 可联系性交叉)**:扫到的达人按两维交叉分组——
  - **首轮合作组** = 垂直度合格(`goodsCategory` 含目标品类)+ 可联系(有 `mailAddress`)。
  - **内容参考组** = 垂直度合格但不可联系,或可联系但垂直度待核(可学内容,未必合作)。
  - ⚠️ 杂货大达人(粉丝高、`goodsCategory` 美妆/3C 杂)常**可联系却垂直度低,不盲进合作组**——契合度评分由 skill 基于 `goodsCategory` 计算(搜索只是召回,数据规范 ⑧),需交叉 `video_search` 源(看达人实际拍过同形态内容)再定。

**call 量**:shop 1 + creator 3~5(goodsCategory 过滤后需翻页凑样本)≈ 4~6 calls。
**止损点**:竞争极高 + 达人极难触达 → 建议「红海 + 无达人通道,慎入」。

**L2 小结卡**要点:事实 → 信号(竞争/达人,**已覆盖 4 维**)→ 建议 → 你来定(停 / 进 L3)。

### L3 · 脚本层(`caption_extract_url`,可选 · 最贵 · 默认不触发)

**触发条件(两个都要)**:① L1/L2 信号支撑「可做」+ ② 用户主动要**脚本级**精细内容方向。
**独立计费**,每个视频 1 call。

> ⚠️ **caption MCP 全地区可用**:个别视频失败属偶发(视频被删/限流等视频级原因,非区域级)。→ **L3 默认全地区跑 caption**:单视频失败换 L1 召回列表下一个重试,连续多个(如 3 个)失败才走下方降级。`is_southeast_asia`:东南亚视频(ID/TH/VN/PH/MY/SG)传 true,其余默认 false。入参/返回/计费详见 [`mcp-reference.md`](mcp-reference.md) §一.5。

**caption 连续多个视频失败的兜底:两档降级(按用户能否提供字幕)**

- **档1 · 用户能自贴字幕/脚本文本**(仍脚本级):用户从其他渠道(TK App 内字幕 / 第三方字幕工具)拿到视频文本 → skill 照下方 7 要素框架拆解,等同 caption 正常。**0 MCP call**。
- **档2 · 无法提供字幕 → video 结构化字段归纳**(降为**方向级**,连续失败兜底):
  1. **复用 L1 已召回 video**(**0 额外 call**),取 3 个代表样本(高播放 / 高互动 / 带货向各 1)。
  2. 每样本提取结构化字段:`title` / `seconds` / `pubTime` / `playCnt`·`likeCnt`·`commentCnt`·`collectCnt`·`interactionRate` / `product.*`。
  3. **归纳(无字幕,只到方向级)**:①内容角度——title 词义归类(开箱/演示/对比/痛点/教程/生活植入);②钩子方向——title 前 15 字 + 高互动样本共性;③节奏参考——seconds 分布看主流时长档;④可复刻性——角度多样 + 中小达人能跑出(非纯头部垄断)。
  4. **产出 = 方向级**(角度 + 钩子方向),**非脚本级**(无逐帧/无演示动作清单/无 CTA 文案)。
  5. **声明**:报告【3 内容方向】标注「L3 字幕拆解未启用,video 结构化字段归纳,方向级非脚本级」。

- **样本**:三类各取 1~3 个——**高播放** / **高互动** / **带货向**。
- **拆解框架**(7 要素):钩子 / 痛点 / 演示 / 卖点 / 证明 / 异议处理 / CTA。
- **信号**:**内容可复刻性**(脚本结构能否被新品复用)。

**call 量**:3~10 calls(按样本数)。
**L3 小结卡**:脚本拆解结论 + 可复刻性 + 对第 5 步内容方向的精细化(方向级 → 脚本级)。

### 层小结卡统一格式(每层填)

```
──── Lx · 层名 ────
【事实】基于本次搜索结果(N 条样本,来源:___)…关键数字
【信号】维度=高/中/低 ｜ 已覆盖 X 维 / 缺口 Y 维
【建议】…(给方向不给命令)
【你来定】▸ 停在这出当前结论   ▸ 进下一层(L?)
```

- skill **永远不硬停**,信号极弱时建议「停或换品」,停/进交用户。
- 每卡标**已覆盖 X 维 / 缺口 Y 维**(支持部分证据判断)。

## §4 第 4 步 · 判断 + 定调

### A. 四维判读汇总

把三层采到的信号填进四维。**采到的判高/中/低(品类基线);没采到的标「未验证」**。

| 判断维度 | 采集来源 |
|---------|---------|
| 商品需求信号 | L1(product) |
| 内容可演示性 | L1 粗判(video 有无演示向)+ L3 精判(脚本演示动作) |
| 内容竞争强度 | L2(shop) |
| 达人可获取性 | L2(creator) |

### B. 档位判定(三选一 + 证据完整度绑定)

| 档位 | 条件 |
|------|------|
| **值得测试** | 四维齐 + 核心无低。**硬要求:至少跑到 L2**(只 L1 够不上) |
| **有条件测试** | 部分中低但需求 + 可演示达标,或证据不全但有戏倾向 |
| **证据不足** | 见下方两义拆分 |

**「证据不足」拆两种语义(不能混)**:
- ① **验了但信号弱** = 真没戏(四维采齐了,但核心维度低 → 产品本身不行)
- ② **没验全** = 没验够,不是没戏(还差几维没采,如只到 L1 缺竞争/达人)

**规则**:用不完整证据**不能给最高档**;**不把「没验够」误判成「没戏」**。

### C. 机会类型定调(判断 → 方案的接口)

**只给「可做」(值得 / 有条件)的品定调;证据不足的不定。** 给**主 + 辅抓手(≤2)**。

| 机会类型 | 触发信号 | 主抓手 |
|---------|---------|--------|
| **品类红利型** | 需求中高 + 竞争低/中 | 宽口径抢位 |
| **差异化型** | 竞争高 + 需求高 + 有可切角度 | 聚焦差异点 |
| **内容驱动型** | 可演示性突出 | 内容创意 / 钩子 |
| **达人撬动型** | 达人可获取性突出 | 达人体系 |

**边界**:「市场教育」不单列——它是**品类红利型的风险标注**(蓝海可能 = 需求还没迁移到 TK,需培育,高风险),定调时若判为品类红利型,必须标注「需求是否已迁移到 TK 待验证」。

> 机会类型 × 方案侧重展开(内容/达人/测试三件套怎么配)见 [`output-blueprint.md`](output-blueprint.md)。

## 降级

| 故障 | 降级 |
|------|------|
| `caption` 连续多个视频失败 | 先换视频重试(L1 召回取下一个);仍失败 → ①用户自贴字幕→脚本级;②否则 video 字段归纳(复用 L1,0 call)→方向级,声明。详见 §3 L3 |
| `shop_search` 报错/不可用 | **三档降级**:① 复用 L1 的 `product_search`/`video_search` 店铺字段(`shopName`/`shopSalesVolume`/`shopProducts`)反推集中度,标「降级估算」(0 call);② 仍需服务指标(`respondRate`/`shipRate`)→ 用户填店铺链接 |
| `creator_search` 不可用 | 用户填达人链接,skill 照常算可获取性 |
| 达人精灵整体不可用 | 用户手填(见 SKILL.md「数据源」手填通路),核心逻辑(0/1必填/2/4/5)仍跑 |
